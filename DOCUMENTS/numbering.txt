# Implement Numbering Mode — SAF Layout App

Quiero implementar ahora el sistema completo de **Numbering** para las Vines.

Antes de modificar código, revisa la arquitectura actual y reutiliza los componentes, tipos y lógica existentes. No quiero duplicar lógica ni romper el comportamiento actual de Grid, Vines, Treatments, long press, click, múltiples Grids o la edición de Vines.

---

# 1. Objetivo general

Crear un modo especial llamado:

**Tools → Numbering**

Su objetivo es asignar y modificar el número físico de cada Vine.

La numeración se realiza después de que el usuario haya terminado de construir el Layout, creado las Vines y asignado sus Treatments.

El campo existente en `Vine` es:

```ts
number: number | null;
```

La numeración debe permanecer guardada en la Vine.

IMPORTANTE:

**Los números no solamente se muestran en Numbering Mode.**

Una vez que una Vine recibe un número, ese número debe mostrarse permanentemente en el plano, incluso cuando el usuario sale de Numbering Mode.

---

# 2. Antes de utilizar Numbering

Antes de entrar a Numbering por primera vez:

```ts
vine.number === null
```

Las Vines no muestran ninguna etiqueta de número.

Visualmente:

```text
●
■
●
```

No mostrar:

```text
Vine 1
Vine 2
Vine 3
```

---

# 3. Primera entrada a Numbering

Cuando el usuario entra por primera vez a:

**Tools → Numbering**

se deben asignar automáticamente números a todas las Vines que:

```ts
treatmentId !== null
```

y que todavía tengan:

```ts
number === null
```

Las Vines sin Treatment quedan completamente fuera del sistema:

```ts
treatmentId === null
```

No reciben número y no muestran número.

---

# 4. Visualización permanente de los números

Después de que Numbering haya sido utilizado por primera vez, cada Vine numerada debe mostrar siempre su número en el plano.

Ejemplo:

```text
● Vine 1
■ Vine 2
● Vine 3
```

Esto debe ocurrir tanto:

* dentro de Numbering Mode;
* fuera de Numbering Mode;
* después de cerrar Numbering;
* después de volver a abrir el Layout.

El texto visual debe ser:

```text
Vine 1
Vine 2
Vine 3
```

La información almacenada sigue siendo solamente:

```ts
number: 1
number: 2
number: 3
```

NO guardar `"Vine 1"` como string.

La etiqueta es solamente presentación.

---

# 5. Gender

Mantener la representación actual:

```text
Female → círculo
Male   → cuadrado
```

La etiqueta `Vine X` debe aparecer junto a la forma sin reemplazarla.

Ejemplo:

```text
● Vine 1

■ Vine 2
```

---

# 6. Numeración independiente por Treatment

Cada Treatment tiene su propia secuencia.

Ejemplo:

```text
Treatment A
Vine 1
Vine 2
Vine 3
Vine 4

Treatment B
Vine 1
Vine 2
Vine 3
```

Por lo tanto:

```text
Treatment A → #1
Treatment B → #1
```

es completamente válido.

Un conflicto solamente existe cuando:

```text
same treatmentId + same number
```

---

# 7. Orden automático

La numeración automática sigue un recorrido físico de tipo **serpiente / zigzag**.

Los Rows se recorren de izquierda a derecha.

### Row 1

Abajo → arriba:

```text
      3
      2
      1
```

### Row 2

Arriba → abajo:

```text
      4
      5
      6
```

### Row 3

Abajo → arriba:

```text
      9
      8
      7
```

### Row 4

Arriba → abajo:

```text
      10
      11
      12
```

Regla:

```text
Row impar → abajo → arriba
Row par   → arriba → abajo
```

La secuencia continúa entre Rows.

---

# 8. Bays y Slots

El orden debe respetar la posición física real de las Vines.

No inventar un nuevo sistema de coordenadas.

Utilizar la geometría y estructura existente de:

```ts
rowNumber
bayIndex
slot
```

La dirección dentro de un Row debe corresponder al eje vertical físico del Grid.

---

# 9. Múltiples Grids

Un Layout puede contener varios Grids.

Los Grids NO tienen numeración independiente.

El recorrido continúa entre ellos.

Orden:

```text
Grid 1 → Grid 2 → Grid 3 → ...
```

Los Grids están actualmente posicionados horizontalmente sobre el eje X positivo.

Por lo tanto, el Grid que está más a la izquierda se procesa primero y los siguientes hacia la derecha después.

Ejemplo:

```text
Grid 1:
Treatment A → 1...30

Grid 2:
Treatment A → 31...60

Grid 3:
Treatment A → 61...90
```

NO reiniciar la numeración al entrar a un nuevo Grid.

La misma secuencia debe mantenerse para cada Treatment.

---

# 10. Nuevas Vines después de Numbering

Si el usuario crea una Vine después de que ya existe numeración:

* no modificar ninguna Vine existente;
* no renumerar el Layout;
* no insertar un número desplazando los demás;
* asignar un número nuevo dentro de su Treatment.

Ejemplo:

```text
1
2
3
4
5
```

Si se crea otra Vine:

```text
1
2
3
4
5
6
```

Aunque físicamente la nueva Vine haya sido creada entre 2 y 3, NO cambiar:

```text
1
2
3
4
5
```

La nueva Vine recibe un número nuevo.

---

# 11. Eliminación de Vines

Cuando se elimina una Vine:

* eliminar también su número;
* NO renumerar las demás.

Ejemplo:

```text
1
2
3
4
5
```

Eliminando #3:

```text
1
2
4
5
```

No convertir automáticamente:

```text
1
2
3
4
```

---

# 12. Volver a entrar a Numbering

Si el usuario sale de Numbering y vuelve posteriormente:

NO recalcular automáticamente toda la numeración.

Las Vines que ya tengan:

```ts
number !== null
```

mantienen exactamente sus números.

Solo considerar Vines nuevas que todavía tengan:

```ts
number === null
```

---

# 13. Reset numbers to default

Dentro de Numbering Mode debe existir una opción claramente visible:

**Reset numbers to default**

Esta opción es DIFERENTE de entrar normalmente a Numbering.

Al pulsarla, el usuario está diciendo explícitamente:

> Quiero descartar la numeración actual y volver a calcularla automáticamente.

Por lo tanto, debe:

1. Ignorar los números actuales.
2. Poner temporalmente las Vines numerables en estado equivalente a `number === null`.
3. Excluir las Vines sin Treatment.
4. Recorrer todos los Grids de izquierda a derecha.
5. Recorrer Rows en zigzag.
6. Reiniciar cada Treatment en `1`.
7. Generar nuevamente toda la numeración.
8. Guardar los nuevos números.

Esto permite corregir completamente una numeración que haya sido modificada manualmente.

---

# 14. Edición manual — Tap

Dentro de Numbering Mode, tocar/click una Vine debe aumentar su número en 1.

Ejemplo:

```text
Vine 7
```

click:

```text
Vine 8
```

click:

```text
Vine 9
```

Esto modifica solamente esa Vine.

No renumerar las demás.

---

# 15. Edición manual — Long Press

Dentro de Numbering Mode, hacer long press sobre una Vine debe establecer:

```ts
number = 1
```

Ejemplo:

```text
Vine 17
```

long press:

```text
Vine 1
```

Esto debe reutilizar la infraestructura de long press que ya existe en la aplicación.

IMPORTANTE:

El comportamiento de Tap/Long Press para Numbering debe estar activo solamente dentro de Numbering Mode.

No romper el comportamiento normal de las Vines fuera de Numbering Mode.

---

# 16. Conflictos

Un conflicto ocurre únicamente cuando dos o más Vines tienen:

```text
same treatmentId
+
same number
```

Ejemplo:

```text
Treatment A

Vine 1 → verde
Vine 2 → verde
Vine 2 → rojo
Vine 3 → verde
```

El texto `Vine X` debe ser:

* verde → número único dentro de su Treatment;
* rojo → número duplicado dentro del mismo Treatment.

IMPORTANTE:

```text
Treatment A → Vine 1
Treatment B → Vine 1
```

NO es conflicto.

---

# 17. Vines sin Treatment

Si:

```ts
treatmentId === null
```

entonces:

* no recibe número;
* no participa en la secuencia;
* no participa en conflictos;
* no muestra `Vine X`.

Debe permanecer visualmente como una Vine normal sin identificación numérica.

---

# 18. Numbering Mode — apariencia visual

Cuando el usuario entra a:

**Tools → Numbering**

el plano debe cambiar ligeramente de apariencia para que sea evidente que está en un modo de edición especial.

No quiero destruir la legibilidad del Grid.

La modificación puede ser sutil, por ejemplo:

* cambio ligero de tono del plano;
* overlay muy suave;
* cambio de tono/opacidad de las líneas;
* indicador visible `NUMBERING MODE`;
* o una combinación de estos.

Debe quedar claro visualmente:

```text
NORMAL MODE
```

versus:

```text
NUMBERING MODE
```

pero sin alterar la geometría ni las posiciones físicas.

---

# 19. Número siempre visible

IMPORTANTE — esta regla tiene prioridad sobre la distinción visual de Numbering Mode:

El número de una Vine NO desaparece al salir de Numbering Mode.

Ejemplo:

Después de Numbering:

```text
NORMAL MODE

● Vine 1
■ Vine 2
● Vine 3
```

Al entrar a Numbering:

```text
NUMBERING MODE

● Vine 1
■ Vine 2
● Vine 3
```

La diferencia es que en Numbering Mode se habilita la edición manual y se muestra claramente que estamos en ese modo.

---

# 20. Herramientas / salida del modo

Numbering debe ser un modo de edición, no una página independiente.

Entrada:

```text
Tools → Numbering
```

Al entrar:

* activar Numbering Mode;
* si es la primera vez, generar números;
* mostrar números;
* habilitar Tap;
* habilitar Long Press;
* mostrar indicador visual de Numbering Mode;
* mostrar opción `Reset numbers to default`.

Al salir:

* desactivar las interacciones especiales de Numbering;
* mantener los números guardados;
* mantener las etiquetas `Vine X` visibles;
* volver al comportamiento normal del Grid.

---

# 21. No modificar todavía Row Numbers

Existe una futura funcionalidad para números visuales de Rows.

NO implementarla ahora.

Los números de Row serán independientes y solamente visuales.

No deben afectar:

* `rowNumber`;
* Bays;
* Vines;
* Treatments;
* Numbering.
